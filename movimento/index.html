Motion & Animation

Princípios de movimento, timing e easing para criar interfaces fluidas e responsivas.

🎬 Princípios de Movimento

Propósito
Toda animação deve ter um propósito. Não anime apenas para animar — use para guiar atenção, comunicar status ou melhorar percepção de performance.
Subtileza
Animações sutis são mais sofisticadas. Movimentos grandes e óbvios parecem amadores. Use easing e timing para criar fluidez.
Consistência
Use os mesmos timing values e easing functions em toda a interface. Consistência cria coerência e previsibilidade.
Performance
Sempre animate transform, opacity. Evite animar width, height, left, right que forçam reflow. Use GPU acceleration.
Acessibilidade
Respeite prefers-reduced-motion. Para usuários sensíveis a movimento, reduza ou disabilite animações.
Feedback
Use movimento para comunicar feedback: hover states, loading states, success/error confirmations. O movimento transmite significado.

⏱️ Timing (Duração de Animação)

Tempos recomendados baseados em tipo de interação e contexto visual. Todos disponíveis como tokens CSS (--transition-*).

100ms

Normal
200ms

Slow
300ms
Modal opens, page transitions
Very Slow
500ms
Loading states, complex animations

📈 Easing Functions

Curvas de easing predefinidas. Cada uma comunica diferente significado e energia. Use ease-out para entradas, ease-in para saídas.

ease-in-out (padrão)
cubic-bezier(0.4, 0, 0.2, 1)
Uso: Transições suaves e naturais. Recomendado para a maioria dos casos.
ease-out (desaceleração)
cubic-bezier(0, 0, 0.2, 1)
Uso: Entradas (fade in, slide in). Começa rápido, termina lento.
ease-in (aceleração)
cubic-bezier(0.4, 0, 1, 1)
Uso: Saídas (fade out, slide out). Começa lento, termina rápido.
linear (constante)
linear
Uso: Progresso indeterminado, loaders. Velocidade constante.

📋 Regras & Gotchas

⚠
Respeite prefers-reduced-motion
Sempre use @media (prefers-reduced-motion: reduce) { animation: none; } para usuários que desabilitaram animações no SO.
✗
Não anime width/height/left/right
Forçam reflows caros. Use transform: translate(), scale() em vez disso. Sempre prefira GPU-accelerated properties.
✓
Use transition shorthand com care
Sempre especifique propriedades: transition: opacity 200ms ease-in-out, transform 200ms ease-in-out;
ℹ
Use will-change com moderação
will-change: transform; em elementos frequentemente animados. Remova após animação terminar para evitar bloat de memória.
